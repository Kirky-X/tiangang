# OCR 安全审查背景预设（按项目类型）

`run_scan.py --ocr` / `--ocr-delegate` 启用 AI 代码审查时，`run_scan.py` 会在 `_ocr_detect_project_type()` 的语言审查背景之上，按检测到的项目类型（`_ocr_project_kind()`）合并本文件对应的逻辑级漏洞猎捕预设（`_OCR_SECURITY_PRESETS`），用户 `--ocr-background` 仍追加在最后。预设是 prompt 级浓缩版；本文件是问题清单的完整蒸馏。

这些维度都是**静态规则抓不到的逻辑级漏洞**——Semgrep 等模式匹配工具不覆盖，须逐工作流推演。素材蒸馏自 CF security-audit 参考集：业务逻辑（ATTACK-CLASSES）、认证（WEB-PROTOCOL-AND-AUTH）、租户隔离（DATA-ISOLATION-AND-LIFECYCLE）、资源耗尽（RESOURCE-EXHAUSTION-AND-AVAILABILITY）。

## 通用猎捕维度（所有项目类型共享）

### 业务逻辑

- **状态机违规**：可否跳步？回退？到达非法状态？重放已完成流程会怎样？部分失败——3 步中第 2 步失败时第 1 步是否回滚？
- **有业务影响的竞态**：并发操作产生非法状态（双花、双审、丢更新）。聚焦"检查-后-使用"非原子的操作。
- **数值/数量篡改**：负值、零值、溢出、精度丢失、字符串与数字之间的类型强转。
- **时间型逻辑**：过期检查、调度、限流窗口、时钟偏移。恰好在边界时刻会发生什么？组件间时区不一致会怎样？
- **隐式信任假设**：来自存储/配置/其他组件/插件的数据，因"入口校验过"就被当安全——若另一条代码路径写入过呢？
- **默认与回退行为**：配置缺失、功能开关关闭、依赖不可用、系统处于迁移中段时，安全姿态是什么？

### 认证

- **JWT 校验与 claim 绑定**：签名校验、服务端固定算法与密钥来源，然后是 `exp`/`nbf`/`aud`/`iss`；`kid`/`jku`/`x5u` 作为不可信 key selector、decode-without-verify 路径。给别的服务签发的合法 token 在这里也是非法的。
- **OAuth/OIDC 请求与回调绑定**：`redirect_uri` 精确归属、`state` 会话绑定、PKCE 与授权码绑定、ID-token 的 issuer/audience/signature/nonce、多 IdP 流程中的选定-IdP 绑定。对比首次回调、重试、移动端 deep-link、账号关联等路由。
- **会话固定与失效**：登录、账号切换、MFA 完成、提权操作后会话标识是否轮换？登出、改密、吊销、禁用后旧会话/refresh token/签名 cookie 是否仍然有效？
- **API-key 作用域与资源绑定**：key 认证到的租户/资源/动作是否超出服务端记录？请求参数可否覆盖绑定？

### 租户隔离

- **租户/属主强制边界缺失**：读、改、删、列、计数、批量查询是否把对象绑定到已认证租户/属主——还是信任 body 字段自报身份？对比直查、嵌套关系、后台、admin、导入、legacy 等路径。
- **复合键与命名空间碰撞**：缓存键、对象路径、搜索文档 ID、临时文件、去重键是否遗漏租户/环境维度？两个主体可否覆盖或取回同一个逻辑键？
- **策略与查询不一致**：行级策略、ORM 默认 scope、授权过滤器与 raw/绕过客户端施加不同的谓词。检查 join、聚合、别名、视图、事务、`unscoped`。
- **副本 ACL 漂移**：主记录的 ACL 或生命周期变化后，可搜索/缓存/索引/缩略图/RSS/预览副本是否失效？检索时是否也过滤（而非只在摄入时）？
- **枚举预言机**：计数、过滤、排序、错误、唯一约束、时延、通知行为可否泄露受保护对象的状态？"不存在"与"无权限"的响应有差异吗？
- **导出/导入边界**：导出可否包含超出访问级别的数据（他人数据、已删/草稿内容、本应清理的历史）？导入/恢复可否绕过属主/ACL/唯一性校验、覆盖现有资源？

### 资源耗尽

- **超线性解析/匹配/求值**：小输入驱动灾难性正则回溯、嵌套解析、递归校验、图遍历、模板展开。推导可接受的深度/基数与复杂度。
- **解压与表示放大**：压缩/稀疏/嵌套/别名/编码输入膨胀后远超传输或文件大小检查——每一级展开之后、跨解析阶段都要有限额（归档、图片、结构化文档）。
- **数据库与下游查询放大**：小请求触发宽扫描、病态 join、扇出、无界排序/聚合——查询深度、过滤基数、分页是否封顶？
- **无界累积**：请求体、乱序流、会话、唯一缓存键、订阅、待处理任务无单项与总量上限；断连/超时/取消后有没有清理。
- **认证前工作量失衡**：昂贵的解析、密钥查找、解压发生在认证与最早的限流闸门之前。
- **配额记账逃逸**：记账维度（IP、路由、租户、key 前缀）可否被攻击者影响，让一个主体的工作逃出预算或消耗另一个主体的配额？
- **取消后分离的工作**：客户端超时/断连/取消作业后，数据库/模型/网络/worker 工作是否仍在跑？取消与 deadline 是否逐层传播？

## 按项目类型的定制侧重

| 项目类型 | 定制侧重（叠加在通用维度之上） |
|---|---|
| Rust（`Cargo.toml`） | 金额/数量计算是否用 checked/带审计的算术（整数溢出在 release 下回绕而非 panic）；`Arc<Mutex>` 跨 `.await` 持锁造成的检查-后-使用窗口 |
| Go（`go.mod`） | `context` 取消后下游工作是否真正停止（取消后分离的工作）；goroutine 并发下共享状态的检查-后-使用窗口 |
| Node/TS（`package.json`） | 字符串-数字强转与精度丢失；原型污染改变解析/查找路径；单请求长期占用事件循环（同步重计算） |
| Python（`requirements.txt`/`pyproject.toml`） | raw 查询/`unscoped` 绕过 ORM 租户 scope；`yaml.load`/`pickle` 嵌套反序列化的解压放大 |
| Flutter/Dart（`pubspec.yaml`） | 客户端代码可被篡改——哪些「校验」只存在于客户端；移动端 deep-link 回调可否伪造 OAuth 绑定 |
| 通用（无以上 manifest） | 只叠加通用四维度 |

## 合并顺序

`run_scan.py` 组装 OCR 背景（`_ocr_thunk` 内）：

1. `_ocr_detect_project_type()` — 语言维度审查背景（安全性/并发/错误处理/性能/测试）
2. `_OCR_SECURITY_PRESETS[kind]` — 本文件对应的逻辑漏洞猎捕预设
3. `--ocr-background` — 用户额外关注，追加在最后

OCR 仅在 `--ocr` / `--ocr-delegate` 显式开启时运行，预设合并不改变 opt-in 边界。
